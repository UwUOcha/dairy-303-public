# Разработка адаптера вуза

## Коротко: что нужно написать

Сайт и боты «Между парами» не знают, откуда ваш вуз берёт расписание: из API,
с HTML-страницы, из Excel-файлов. Эту часть пишете вы. Программа называется
**адаптер**. Это маленький веб-сервер на любом языке, который:

1. получает расписание из источника вашего вуза (API, парсинг сайта, файлы);
2. приводит его к одному общему формату JSON, описанному ниже;
3. отдаёт этот JSON по нескольким URL.

Сами вы адаптер никуда не отправляете. Ядро платформы (`raspd`) раз в какое-то
время **само** обращается к нему по HTTP, например
`GET http://adapter:8310/v1/schedule?group=…&from=2026-09-01&to=2026-09-30`,
сохраняет ответ в свою базу и уже из неё показывает расписание на сайте и в ботах.
Адаптеру не нужны база платформы, пользователи и токены ботов.

```text
сайт/API/файлы вуза  ──(ваш код: скачать и разобрать)──►  адаптер
адаптер  ◄──(GET /v1/…, ядро спрашивает само)──  raspd  ──►  сайт и боты
```

Нужно ответить на четыре запроса (пятый, `/v1/teachers`, необязателен):

**`GET /health`** — «процесс жив»: `{"status": "ok"}`.

**`GET /v1/info`** — кто вы:

```json
{"version": "1", "source": "example-university", "timezone": "Europe/Moscow", "staff_directory": false}
```

**`GET /v1/catalog`** — список всех групп:

```json
{
  "complete": true,
  "fetched_at": "2026-09-23T13:43:16Z",
  "departments": [{"id": "faculty:science", "name": "Факультет наук"}],
  "groups": [
    {"id": "group:alpha", "name": "Альфа", "department_id": "faculty:science", "course": 1, "active": true}
  ]
}
```

**`GET /v1/schedule?group=group:alpha&from=2026-09-07&to=2026-09-13`** — все
занятия группы за эти даты (не больше 31 дня):

```json
{
  "group_id": "group:alpha",
  "from": "2026-09-07",
  "to": "2026-09-13",
  "complete": true,
  "status": "published",
  "fetched_at": "2026-09-23T13:43:16Z",
  "lessons": [
    {
      "id": "math:alpha:2026-09-07",
      "date": "2026-09-07",
      "start": "09:15",
      "end": "10:35",
      "subject": "Математика",
      "kind": "Лекция",
      "room": "Кампус А, 101",
      "teachers": [{"id": "person:ada", "name": "Анна Примерова"}]
    }
  ],
  "subgroups": []
}
```

Каждый `id` придумываете вы, это любые строки. Главное — один и тот же объект
должен получать одинаковый `id` при каждом запросе, иначе ядро примет его за
новый. `fetched_at` — время, когда вы получили данные из источника вуза.

## Что именно запрограммировать

HTTP-часть писать не нужно: она уже есть в `examples/adapter-json/server.py`
(стандартная библиотека Python, без зависимостей). Файл разделён на две части.
«Общую часть» с HTTP-ответами оставьте как есть, а в «вашей части» перепишите
четыре функции:

| Функция | Что возвращает | Откуда брать у себя |
|---|---|---|
| `load_source()` | постоянное имя установки (`"my-university"`) и часовой пояс (`"Europe/Moscow"`) | просто константы |
| `load_catalog()` | список факультетов и список групп | страница или API со списком групп |
| `load_lessons(group, start, end)` | пары группы за даты и её подгруппы | страница или API расписания группы |
| `load_teachers()` | справочник преподавателей или `None` | не обязательно: верните `None` |

Главная работа — `load_lessons`. Допустим, на сайте вуза расписание группы
ИВТ-21 выглядит так:

```text
Понедельник 07.09   2 пара   10:10–11:40   Математика (лекция)   Иванов И. И.   ауд. 305
```

Ваш код скачивает эту страницу, разбирает её и превращает каждую пару в словарь:

```python
{
    "id": "ivt-21:2026-09-07:2",    # группа + дата + номер пары
    "date": "2026-09-07",
    "start": "10:10",
    "end": "11:40",
    "subject": "Математика",
    "kind": "лекция",
    "room": "ауд. 305",
    "teachers": [{"name": "Иванов И. И."}],
}
```

Функция возвращает список таких словарей: все пары группы с `start` по `end`
включительно. Если у вуза расписание отдаётся по неделям, скачайте нужные недели
и лишнее отбросьте.

Порядок работы:

1. Разберитесь, где у вашего вуза лежат список групп и расписание группы, и
   научитесь скачивать их любым удобным способом.
2. Перепишите `load_catalog()`. В качестве `id` группы подойдёт её номер из
   источника или имя из URL: главное, чтобы он не менялся.
3. Перепишите `load_lessons()`, как показано выше.
4. Запустите `python3 examples/adapter-json/server.py`, а в другом терминале
   `PROVIDER_URL=http://127.0.0.1:8310 make check-adapter`. Проверка скажет,
   что не так с ответами. Исправляйте, пока она не пройдёт.
5. Запустите всю платформу со своим адаптером
   ([NEW_UNIVERSITY.md](NEW_UNIVERSITY.md)) и посмотрите расписание на сайте.

Два правила, которые проще соблюсти сразу:

* Если источник не ответил или ответил с ошибкой, бросьте исключение, а не
  возвращайте пустой список. Пустой список означает «у группы действительно нет
  пар», и ядро сотрёт сохранённое расписание.
* Не долбите сайт вуза: ядро запрашивает группы по очереди, но делает это
  регулярно. Кэшируйте скачанное и ограничивайте частоту запросов.

Писать на Python необязательно. Годится любой язык, если сервер отвечает тем же
JSON. Всё, что ниже, — справочник с точными правилами для подгрупп, общих
лекций, неполных ответов и ошибок. Возвращайтесь к нему по мере необходимости.

## Устройство

Одна установка платформы обслуживает один вуз и подключается к одному источнику.
Адаптер не открывает базу ядра, не знает пользователей и не отправляет
уведомления. Ядро запрашивает каталог и расписание, проверяет ответы, хранит их
в SQLite и обслуживает сайт и ботов. Данные примера вымышлены; его еженедельный
шаблон нужен для проверки интеграции, а не для определения реальных учебных
периодов.

## Контракт v1

Машиночитаемый контракт: [provider.openapi.json](provider.openapi.json).
Go-типы: `pkg/provider`. Генератор: `go run ./cmd/provider-schema`.
`make check-schema` проверяет, что документ соответствует типам.

| Метод | Ответ |
|---|---|
| `GET /health` | Жив ли процесс; доступность вуза не влияет на эту проверку |
| `GET /v1/info` | Версия контракта, постоянный `source`, часовой пояс, возможности |
| `GET /v1/catalog` | Полный каталог подразделений и групп |
| `GET /v1/schedule?group=…&from=…&to=…` | Полное расписание группы за включительный диапазон |
| `GET /v1/teachers` | Необязательный расширенный справочник преподавателей |

Сейчас ядро запрашивает календарные месяцы. Контракт ограничивает запрос 31 датой;
адаптер, получающий данные по неделям или целиком, сам собирает этот диапазон.
Постраничный upstream адаптер вычитывает до конца, проверяя согласованность страниц,
и только после этого возвращает полный ответ. Пагинации между ядром и адаптером
в v1 нет. Лимит ответа — 32 MiB, таймаут HTTP-клиента ядра — 110 секунд.

`source` — постоянный идентификатор установки источника, например `example-university`.
Он не должен меняться при перезапуске или выпуске новой версии адаптера. Ядро
фиксирует его в базе и отказывается импортировать другой вуз поверх существующей
установки. `version` должен быть строкой `"1"`. `timezone` — IANA, например
`Europe/Berlin`; он должен совпадать с профилем установки.

При заданном служебном токене используйте `Authorization: Bearer …`.
В Compose задайте `PROVIDER_TOKEN`: ядро получит его как `PROVIDER_TOKEN`, адаптер —
как `ADAPTER_TOKEN`. Порт адаптера наружу не опубликован. На разных машинах
используйте HTTPS и служебный токен. Перенаправления HTTP-клиент не выполняет.
Ключи API вуза хранятся только у адаптера.

## Идентичность и обновления

ID — непустые строки до 256 символов, стабильные между запросами и перезапусками.
Они уникальны по виду сущности внутри источника. Подгруппы должны иметь глобальные
ID, например `group-a:lab-1`, а не повторяющееся `1` у каждой группы. Числовые
внутренние ID ядра — отдельная сущность: их нельзя вычислять по внешнему ID.

Занятие — конкретное событие на конкретную дату. Для периодического шаблона
подходит `template-id:2026-09-07`. ID не меняется при переносе времени, аудитории
или предмета. Если источник не даёт ID, адаптер поддерживает собственное устойчивое
сопоставление; хеш всех изменяемых полей не является стабильным ID занятия.

Общая лекция может приходить в расписания нескольких групп с одним ID. Все её
общие поля должны совпадать. Ядро хранит отдельные связи занятия с каждой лентой:
исчезновение из одной группы не удаляет его из остальных.

Имена групп и ФИО не считаются доказательством идентичности. `teacher.identity`
необязательно: одинаковое непустое значение явно объединяет несколько аккаунтов
преподавателя. Передавайте его только при подтверждённом соответствии. Если ID
преподавателя неизвестен, передайте имя без ID; ядро не объединит однофамильцев
из разных занятий автоматически.

Для замены записи группы каталог содержит `replacements: [{"from":"old","to":"new"}]`.
Ядро переносит пользователей по этому явному указанию. Дополнительный флаг
`match_subgroups_by_name: true` разрешает перенос выбора подгруппы по точному имени;
для ещё не загруженного каталога подгрупп переход откладывается. Без флага выбор
подгруппы сбрасывается. `hidden` управляет видимостью группы в поиске. Правила
определения дубликатов остаются в адаптере. Одноимённые группы допустимы.

## Полнота и свежесть

Каждый успешный ответ каталога и справочника содержит `complete: true` и
`fetched_at` в RFC3339. У расписания также обязательны точные `group_id`, `from`,
`to`, `status: "published"`, массивы `lessons` и `subgroups` (пустой массив — `[]`,
не `null` и не отсутствие поля).

* `published` + `complete: true` + `lessons: []` означает подтверждённое отсутствие
  занятий в указанном диапазоне. Только такой ответ может удалить сохранённые пары.
* `status: "unpublished"` или `complete: false` сохраняют предыдущие данные в ядре;
  импорт завершается ошибкой, отметка свежести не обновляется.
* При ошибке upstream возвращайте HTTP-ошибку, а не пустое расписание.
* `fetched_at` означает получение данных из источника. При отдаче кэша сохраняйте
  исходную дату; текущее время HTTP-ответа не делает кэш свежим.
* Более старый снимок месяца не заменяет новый. Повтор того же снимка не создаёт
  уведомление. Расписание, подгруппы и метаданные импорта записываются транзакционно.

Полный справочник подгрупп должен описывать действующий выбор для этой группы
независимо от запрошенного месяца. Имена старых подгрупп сохраняются для истории,
но удалённые подгруппы исключаются из выбора.

Ошибки: JSON `{"code":"unavailable","message":"Source temporarily unavailable"}`.
Поддерживаемые коды: `unauthorized` (401), `invalid_request` (400), `not_found` (404),
`rate_limited` (429), `not_supported` (501), `upstream_error`/`upstream_auth` (502),
`unavailable` (503). Не включайте секреты upstream в ответы и журналы.

## Время, участники и дополнительные возможности

`date` — ISO-дата по часовому поясу вуза; `start`/`end` — `HH:MM` в том же поясе.
У каждого занятия собственное время. Если оно неизвестно, обе строки пустые.
В v1 начало и конец известного времени находятся в одних сутках; ночное занятие
через полночь следует разделить на события с разными ID и датами.

`slots` — необязательная сетка звонков с полями `id`, `start`, `end`, `number`.
Занятие с `slot_id` должно соответствовать времени слота. Без сетки ядро сохраняет
время, но не выдумывает номер пары. Изменение времени слота не переписывает ранее
сохранённые недели или занятия другой группы.

`workdays` — учебные дни группы от 1 (понедельник) до 7 (воскресенье). Если данных
нет, действует исторический резервный режим понедельник–суббота. Индивидуальные
занятия в выходной сохраняются и видны в дневном расписании.

`audience` принимает `group`, `subgroup`, `flow`, `combined`. Для `subgroup` задайте
`subgroup_id` из массива `subgroups`. Общие занятия включайте в каждую ленту группы,
для которой они предназначены. Подмножество нескольких подгрупп одной группы в v1
представляйте отдельными событиями с устойчивыми ID для каждой подгруппы;
`subgroup_ids` у combined служит описанием участников, не произвольным ACL фильтра.
`audience_label`, `group_names`, `subgroup_names` помогают подписать сборную аудиторию.
У `combined` исходная `subgroup_id` может принадлежать другой группе: тогда её
имя обязательно в `subgroup_names`; добавлять её в местный список `subgroups` нельзя.
В словарях достаточно имён участников возвращаемых занятий и запрошенной группы;
передавать весь каталог в каждом ответе не требуется. Ядро проверяет словари,
но выделяет локальные ID только для записей, используемых при сохранении месяца.

`visibility` содержит явные решения адаптера о видимости групп. Отсутствие ID
означает «не менять», а `false` — «показать». В месячном ответе достаточно решений
для затронутых групп, включая их двойников; полный снимок видимости передаётся
через каталог. Повторный запрос должен снова возвращать нужные решения, поскольку
ядро могло не получить или не сохранить предыдущий ответ.

`kind` может содержать подпись источника. Для испытаний доступны общие значения
`exam`, `credit`, `graded_credit`, `consultation`, `coursework`; они отображаются
как экзамен, зачёт и т. д. Русские сокращения прежнего адаптера сохраняют поддержку.

Расширенный справочник преподавателей необязателен: установите `staff_directory: false`.
Преподаватели из занятий продолжат работать в поиске и расписании. Справочник
дополняет эти данные ФИО, степенью, кафедрами; список `vacancies` явно исключает
служебные записи. Ядро не требует отдельного токена преподавательского виджета.

## Проверка своего адаптера

```sh
python3 examples/adapter-json/server.py
# В другом терминале:
PROVIDER_URL=http://127.0.0.1:8310 make check-adapter
```

Проверка вызывает info, каталог, месяц первой активной группы и справочник, если
он объявлен. Это проверка контракта на выборке, а не аудит всего расписания.

Для полной проверки реализации платформы:

```sh
make vet test test-ui check-boundaries check-schema
```

`tests/ecosystem_test.go` запускает отдельный Python-адаптер, настоящий API ядра,
сайт и сценарии бота. Проверки импорта дополнительно покрывают строковые ID,
повторные обновления, удаление в пределах одной группы, недоступность адаптера,
перенос времени без изменения чужой группы и сохранение различных преподавателей.

Добавление необязательных полей совместимо с v1. Изменение значения существующего
поля, обязательных полей или семантики удаления требует новой основной версии.
Ядро отклоняет неизвестную основную версию. Публикуйте адаптер и платформу
независимо; их связью является версия этого контракта.

## Метаданные и идентификаторы в ядре

Успешный `/v1/info` кэшируется на пять минут; загрузка каталога принудительно
перепроверяет источник и возможности адаптера. Изменение возможностей обычно
подхватывается при следующем обновлении каталога или по истечении кэша. При ошибке
перепроверки старые метаданные не используются для новых импортов. Менять вуз
по работающему URL нельзя: во время действия кэша ответы v1 не содержат отдельного
`source`; для другой установки нужны другой процесс ядра и отдельная база.

При `staff_directory: false` синхронизатор не отмечает попытку импорта и не вызывает
`/v1/teachers`. Вызовы справочника напрямую также проверяют эту возможность.
ID одного ответа сопоставляются пакетом: известные ID читаются из базы, новые
создаются одной транзакцией. Это сохраняет соответствия между перезапусками
и не занимает единственного писателя для уже известных ID.

`vacancies` содержит уникальные непустые ID без пересечения с `teachers`.
Невалидный ответ отклоняется целиком, чтобы не удалять привязки преподавателей.
