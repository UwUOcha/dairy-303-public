# Админка внутри сайта

Панель открывается на `/admin/` и работает в процессе `webd`. Использует тему,
настройки оформления и навигацию основного сайта. В ней сохранены метрики
сервисов, пользователей, рассылок и ресурсов машины, графики истории и ошибки.
Она по-прежнему предназначена для наблюдения, без операций изменения данных.

Для каждого запроса — HTML, JavaScript, статистики и истории — одновременно нужны:

1. Действующая веб-сессия Telegram/VK-аккаунта, совпадающего с `admin_tg` или
   `admin_vk` в профиле установки. Проверяется пара «площадка + ID».
2. IP клиента из `ADMIN_ALLOW_IPS`.

Это вход через аккаунт с дополнительным ограничением по сети. В строгом смысле
это не классическая двухфакторная аутентификация: IP не является независимым
секретом. Пароля или OTP поверх уже существующего входа через бота здесь нет.

## Включение

Укажите ID администратора в общем JSON-профиле `raspd` и `webd`, например:

```json
{"admin_tg":"123456789"}
```

Добавьте поле к своему полному профилю. У администратора должен быть настроен
бот соответствующей площадки. Администратору разрешён вход без отдельного
добавления в список участников закрытой установки; удаление его ID из профиля
после перезапуска снимает административные права.

Скопируйте `deploy/admin.env.example` в `deploy/admin.env`:

```dotenv
ADMIN_ENABLED=true
ADMIN_ALLOW_IPS=203.0.113.7
WEB_TRUSTED_PROXIES=172.20.0.2
```

Адреса в примере документационные — замените их своими. `ADMIN_ALLOW_IPS` содержит
адрес клиента, `WEB_TRUSTED_PROXIES` — адрес доверенного reverse proxy. Приватные
подсети и loopback не становятся доверенными автоматически. При пустом списке
proxy учитывается только TCP-адрес соединения, заголовки игнорируются.
Доверенный proxy обязан **перезаписывать** `X-Forwarded-For` единственным адресом
клиента. Цепочки, отсутствие или некорректное значение от доверенного proxy
отклоняются. Не включайте всю сеть Docker в доверенные, если там есть чужие сервисы.

Задайте точный HTTPS origin в `public_url` профиля или `WEB_PUBLIC_URL`.
Базовый Compose подключает `deploy/admin.env` к webd и сохраняет историю в томе
`admin_db`. По умолчанию ресурсы измеряются внутри контейнера. Для метрик хоста
добавьте `-f compose.admin-host.yaml`: этот необязательный overlay монтирует
`/proc` и файловую систему хоста только для чтения. После настройки перезапустите `raspd` и `webd`, войдите через бота.
При выполнении обоих условий ссылка «Админ-панель» появится в навигации
и настройках сайта. Прямой переход на `/admin/` также доступен.

Запросы панели не кэшируются в HTTP, service worker или локальном хранилище.
Просроченная/отозванная сессия, неподходящий ID или IP закрывают API. Недоступность
ядра не даёт обойти проверку сессии. Вкладка очищает данные при завершении доступа
и не восстанавливает старые метрики через историю браузера.
