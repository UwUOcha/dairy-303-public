# Доступ по списку и вход через бота

Режим доступа выбирается в [профиле установки](PROFILES.md):
`access: public` открывает расписание всем, `access: allowlist` требует входа
и допуска пользователя. Профиль по умолчанию закрытый; пример вымышленного
вуза явно включает публичный режим.

Для закрытой установки задайте точный HTTPS origin в `public_url` (либо
`WEB_PUBLIC_URL`) и ссылки на настроенных Telegram/VK-ботов. Один и тот же
профиль нужен `raspd`, `botd` и `webd`. В профиле перечисляются администраторы
площадок; токены самих ботов передаются через переменные окружения.

Пользователь выбирает площадку на `/login`, переходит в личный диалог с ботом
и вводит полученный восьмизначный код в исходном браузере. Если VK не передал
параметр ссылки, интерфейс предлагает скопировать команду `/login …`.
Запрос действует пять минут; пять неправильных попыток блокируют его.
Для завершения входа нужны одновременно код и cookie исходного браузера.

Сессии хранятся на сервере. Cookie `__Host-mp_session` имеет флаги Secure,
HttpOnly, SameSite=Lax и срок 60 дней. На один аккаунт площадки разрешено
четыре сессии. Telegram и VK автоматически не объединяются. Раздел
«Устройства и выход» позволяет отзывать сессии; команда бота `/web_logout`
предлагает подтверждение выхода на всех устройствах.

Группа и подгруппа при входе берутся из настроек бота, затем сайт хранит свой
выбор. Администратор управляет допуском через приватный Unix-сокет `raspd`:

```sh
curl --fail-with-body --unix-socket /run/rasp/api.sock \
  -H 'Content-Type: application/json' \
  --data '{"op":"allow","platform":"tg","ext_id":"ЧИСЛОВОЙ_ID"}' \
  http://rasp/web-auth
```

Укажите фактический путь сокета своей установки. Операция `deny` удаляет
участника, его сессии и незавершённые входы; повторный `allow` безопасен.
Этот маршрут недоступен через публичный сайт. Публичный режим не требует
присутствия в списке.

Настройте reverse proxy так, чтобы клиент не мог подменить доверенные
заголовки адреса. Админка встроена в `webd` и требует одновременно
аккаунт администратора и разрешённый IP — [настройка](ADMIN.md). Личный API также проверяет собственный ключ независимо
от браузерной сессии — см. [BOT_API.md](BOT_API.md).
