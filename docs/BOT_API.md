# Личный API для ИИ-бота

Доступ только для Telegram-пользователя, чей ID задан в поле `bot_key_owner` профиля.
При пустом значении выпуск ключа отключён. На всю установку можно
выпустить **один** активный ключ. В интерфейсе сайта управления ключами нет;
белый список закрытой беты не даёт другим пользователям права выпускать ключи.

## CLI на сервере

Из `/opt/rasp`, при работающем `raspd`:

```bash
docker compose exec -T raspd /usr/local/bin/raspd -bot-key status

# Создать: stdout содержит только ключ. Сохранить в файл с закрытыми правами.
umask 077
docker compose exec -T raspd /usr/local/bin/raspd -bot-key create > /root/dairy-bot-api.key

# Перевыпустить (старый ключ немедленно перестанет работать).
docker compose exec -T raspd /usr/local/bin/raspd -bot-key rotate > /root/dairy-bot-api.key.new &&
  mv /root/dairy-bot-api.key.new /root/dairy-bot-api.key

# Отозвать без выпуска нового.
docker compose exec -T raspd /usr/local/bin/raspd -bot-key revoke
```

Повторный `create` вернёт ошибку, сохранив действующий ключ. Не перенаправляйте
его повторно в файл с уже сохранённым секретом: shell очистит файл до запуска
команды. `status` показывает только наличие ключа и дату создания.
Для установки без Docker: `RASP_SOCKET=/run/rasp/api.sock raspd -bot-key …`.
Команды обращаются к приватному Unix-сокету; отдельный процесс не открывает SQLite.

Перед созданием ключа владелец должен выбрать группу в Telegram-боте.
Группа и подгруппа читаются из его настроек заново при каждом запросе;
передавать их в API нельзя. Изменение группы в боте не требует нового ключа.
Ключ действует до отзыва или перевыпуска и переживает перезапуск. Выход с сайта
его не отзывает: он независим от браузерных сеансов и списка участников беты.

В базе хранится только SHA-256 случайного ключа с 256 битами энтропии.
Полный ключ возвращается исключительно при создании/перевыпуске.
Миграция SQLite 12 → 13 применяется автоматически, ключ сама не создаёт.

## Подключение бота

Базовый адрес — ваш домен и путь `/api/bot`, например: `https://schedule.example.edu/api/bot`.
Ключ передаётся только заголовком `Authorization: Bearer …` по HTTPS
([формат Bearer, RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1)).
Cookie, вход в браузере и ключ в query string не заменяют этот заголовок.

```bash
export DAIRY_API_KEY='ключ из CLI'
curl --fail-with-body -sS \
  -H "Authorization: Bearer $DAIRY_API_KEY" \
  https://schedule.example.edu/api/bot/schedule/week
```

Все методы — `GET`, ответы — JSON. Часовой пояс берётся из профиля установки.

| Путь относительно `/api/bot` | Данные и параметры |
|---|---|
| `/me` | Текущая группа, подгруппа, сегодняшняя дата, часовой пояс, `scope: schedule:read` |
| `/schedule/day` | День; `date=YYYY-MM-DD`, `today` или `next`; по умолчанию сегодня. `next` — следующий учебный день |
| `/schedule/week` | Неделя; `monday=YYYY-MM-DD`, по умолчанию текущая. Любая дата нормализуется к понедельнику |
| `/schedule/now` | Текущая пара, следующая сегодня, оставшиеся пары |
| `/schedule/next-lesson` | Ближайшая пара в пределах 14 дней; `from=tomorrow` начинает поиск с завтрашнего дня |
| `/schedule/upcoming` | 30 дней начиная с `date=YYYY-MM-DD` (по умолчанию сегодня) |
| `/schedule/exams` | Экзамены, зачёты и консультации на ближайшие 180 дней |
| `/changes/dates` | Даты недавних изменений расписания группы |
| `/changes/day` | Расписание до/после правки; обязательный `date=YYYY-MM-DD` |

Формат расписания совпадает с внутренним API: `group`, `subgroup`, `today`,
`day.items` или `week.days[].items`. Занятия содержат предмет (`discipline`),
преподавателей (`staff`), аудиторию (`classroom`), дату, начало и конец в минутах
от полуночи (`minute_from`, `minute_to`). Подгруппа фильтруется на сервере,
общие занятия сохраняются. Ответ `/me` не раскрывает настройки уведомлений
и прочие поля пользователя.

ИИ-бот должен учитывать `missing: true` (не все месяцы загружены) и
`stale: true` (данные устарели), а также `fetched_at` там, где они присутствуют.
Пустое расписание при `missing: true` не означает, что занятий точно нет.
Экзамены читаются из локальной копии и не имеют полей полноты; отсутствие
`items` не гарантирует отсутствие экзаменов у вуза.
`/changes/dates` относится к группе целиком; `/changes/day` фильтрует занятия
по подгруппе и полем `known` указывает, сохранился ли снимок до изменения.

Ошибки: `401 invalid_token` — нет действующего ключа;
`400 invalid_query` — лишние, повторные или некорректные параметры;
`409 group_not_configured` — у владельца больше не выбрана группа;
`429` — лимит запросов, повторить после `Retry-After`;
`503` — временная недоступность. Неизвестные маршруты возвращают `404`,
методы записи — `405`. API ограничен чтением перечисленных данных:
админка, пользователи, сообщения, настройки и управление ключом недоступны.

Лимит личного API: 2 запроса/с, короткий всплеск до 20; действует также общий
лимит сайта. Ответы не кэшируются HTTP-кэшами. Для личного помощника достаточно
получать неделю или день по запросу пользователя.
