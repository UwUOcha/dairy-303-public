# Профиль установки

Сервисы платформы загружают один JSON-файл по `RASP_PROFILE` при старте.
По умолчанию используются нейтральные настройки (UTC, название «Университет»,
доступ по списку). Для рабочего запуска задайте профиль явно. В Compose путь на
хосте задаётся через `RASP_PROFILE_FILE`, внутри контейнеров он одинаковый.

Пример: `profiles/example.json`. Изменение профиля требует
перезапуска сервисов; отдельная сборка не нужна. Браузер получает только публичные
поля через HTML и `/api/config`, административные ID туда не попадают.

| Поля | Назначение |
|---|---|
| `app_name`, `university`, `location_label` | Название сайта, вуза и подпись кампуса |
| `source_name`, `source_url` | Подпись и ссылка источника |
| `public_url` | Внешний origin сайта, без пути; обязателен для входа по списку |
| `timezone` | Часовой пояс IANA, одинаковый с `/v1/info` адаптера |
| `term_starts` | Начала учебных периодов в формате `MM-DD`; поддерживает семестры и триместры |
| `telegram_url`, `vk_url` | Ссылки на ботов, включая ссылки входа; отсутствующая площадка скрывается |
| `web_mark` | Короткий знак сайта и админки; по умолчанию первая буква `app_name` и точка |
| `brand_mark`, `brand_sign`, `description` | Подписи в боте и описание сайта |
| `accent` | Основной дополнительный цвет `#RRGGBB` |
| `access` | `public` — открытое чтение сайта; `allowlist` — прежний вход через бота и список допуска |
| `admin_tg`, `admin_vk` | Администраторы и получатели обратной связи; для админки дополнительно нужен разрешённый IP |
| `bot_key_owner` | Telegram ID владельца личного API; пусто — создание ключа недоступно |
| `assets_dir` | Каталог замены публичных изображений внутри контейнера |
| `texts` | Переопределения `onboarding`, `about`, `share` |

Профиль не содержит токенов платформ, API вуза и служебного Bearer-токена.
`TELEGRAM_TOKEN`/`VK_TOKEN` передаются только botd. Учётные данные API вуза — только его адаптеру.
Старые `ADMIN_TG_ID`, `ADMIN_VK_ID`, `BOT_LINK_TG`, `BOT_LINK_VK` могут переопределять
настройки botd для совместимости; новые установки должны использовать профиль,
чтобы ссылки бота и сайта совпадали.

В `texts` разрешены шаблоны `{{university}}`, `{{app_name}}`, `{{source_name}}`,
`{{public_url}}`, `{{brand_mark}}`, `{{brand_sign}}`. Подставляемые значения
экранируются для сообщений. `about` содержит один `%s` для счётчика пользователей,
`share` — один `%s` для ссылки; литеральный процент в них записывается как `%%`.
Это доверенные шаблоны оператора с разметкой Telegram HTML.

Для изображений положите в `assets_dir` нужные файлы `icon.svg`, `app-icon-192.png`,
`app-icon-512.png`, `og.png`. Каталог монтируется отдельно только для чтения в webd;
прочие имена файлов через него не обслуживаются. Например, установите
`"assets_dir":"/etc/rasp/branding"` и добавьте в Compose overlay:

```yaml
services:
  webd:
    volumes:
      - ./branding:/etc/rasp/branding:ro
```

Без замен используются общие изображения «Между парами». Манифесты PWA получают
название из профиля автоматически. Service worker обновлён, чтобы старый набор
модулей не оставался после перехода.

Персональный API сохраняет прежние ограничения: один ключ, управление через
локальный сокет, доступ к группе владельца. Изменение `bot_key_owner` лишает
прежний ключ доступа; `rotate` привязывает новый ключ к новому настроенному
аккаунту. Права не выводятся из наличия веб-сессии.

У новых пользователей сохраняется IANA-пояс установки, если не задано отдельное
фиксированное смещение. Перед рассылкой вычисляется актуальное смещение, включая
сезонный перевод часов. При миграции прежнее смещение, совпадающее с поясом
установки, привязывается к этому поясу; явно отличающееся смещение сохраняется.

Админка встроена в сайт: [настройка двух проверок доступа](ADMIN.md).

Страница `/source` доступна без входа и показывает исходники и лицензии.
`WEB_SOURCE_CODE_URL` переопределяет ссылку, встроенную сборкой (`SOURCE_CODE_URL`).
Для модифицированной версии укажите её соответствующие исходники.
