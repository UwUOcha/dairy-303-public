# Сайт и PWA

`webd` читает расписание через приватный HTTP API `raspd` по Unix-сокету.
База пользователей и ключи API вуза ему не передаются. Название, ссылки, часовой
пояс, учебные периоды и оформление задаются [профилем установки](PROFILES.md).

Сайт показывает неделю и день, предметы и преподавателей, сессию, изменения
расписания, подгруппы и избранные группы. Время занятий задаёт адаптер; номера
пар и сетка звонков необязательны. Сохранённое расписание ядро отдаёт и при
недоступности адаптера, обозначая устаревшие или отсутствующие месяцы.

Для локального запуска используйте `make run-adapter-json`, `make run-rasp` и
`make run-web` в отдельных терминалах. `make preview-web` запускает только
демонстрацию интерфейса. Полный запуск через Docker описан в [README](../README.md).

Режим `access: public` открывает расписание без входа. Режим `access: allowlist`
требует входа через бота и допуска в список — см. [управление доступом](BETA.md).
Для личного API в обоих режимах необходим отдельный ключ.

В production установите точный HTTPS origin в `public_url` профиля или
`WEB_PUBLIC_URL`, настройте свой reverse proxy и передавайте всем процессам
одинаковый профиль. Админка работает в этом же процессе на `/admin/`, см. [настройку](ADMIN.md).
В базовом Compose сайт опубликован на `127.0.0.1:8306`.
При изменении профиля перезапускайте процессы. Для собственного логотипа,
иконок PWA и изображения ссылки предусмотрен `assets_dir`.

Проверки интерфейса: `make test-ui`. Проверки маршрутов, авторизации и профиля:
`go test ./internal/web`. Сквозной тест с независимым адаптером: `go test ./tests`.
